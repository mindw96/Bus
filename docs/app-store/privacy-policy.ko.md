## 2. 처리하는 정보와 목적

### 일반 버스 조회

앱은 자체 서버에 선택한 정류장의 도착 정보를 요청합니다. 서버는 교통정보 제공기관의 데이터를 조회·가공하여 반환합니다. 서비스 운영, 요청 보호와 장애 대응을 위해 접속 IP 주소, 클라이언트 정보(User-Agent), 요청 주소·방식, 응답 상태, 처리 시간, 요청·응답 크기, 통신 방식 및 서버 주소가 요청 로그에 기록됩니다. 일반 조회의 요청 로그는 잠금화면 버스 추적을 사용하지 않아도 발생합니다.

### 잠금화면 버스 추적

사용자가 안내를 확인하고 원격 추적에 동의하면 다음 정보를 서버에 전달하여 선택한 버스의 Live Activity를 갱신합니다. 일부 오류 로그에는 추적 세션 식별자와 노선·정류장 정보, 전달 상태와 오류 코드가 함께 기록됩니다.

| 정보 | 사용 목적 |
| --- | --- |
| 앱이 생성한 설치 식별자 | 같은 앱 설치의 추적 등록·중단 요청 확인, 중복 요청 및 과도한 요청 제한 |
| Live Activity 알림 전달 토큰 | 사용자가 선택한 잠금화면 버스 정보 갱신 |
| 추적 세션 식별자, 선택한 노선·정류장·운행 정보, 도착 예정 시각 | 선택한 버스의 정보를 찾아 갱신하고 추적을 종료 |
| 추적 생성·갱신·종료 시각, 전달 상태와 오류 정보 | 갱신 재시도, 서비스 안정성 확인 및 장애 대응 |

기기의 GPS 위치를 수집하지 않으며 현재 위치 권한을 사용하지 않습니다. 다만 선택한 정류장·노선과 시각은 사용자의 이동 계획이나 방문 장소를 추론하는 단서가 될 수 있습니다. 이 선택 정보로 사용자의 실제 위치를 산정하는 기능은 제공하지 않습니다.

운영자는 이러한 정보를 버스 기능 제공, 요청 보호와 오류 대응을 위해 사용하며, 광고나 타사 앱·웹사이트에 걸친 광고 추적 목적으로 사용하지 않습니다.

### 지원 문의

앱 기능을 사용하기 위해 이름·이메일·전화번호·주소록·사진·마이크 정보를 요구하지 않습니다. 이용자가 지원 연락처로 문의하는 경우에는 답변용 이메일 주소, 문의 내용과 자발적으로 제공한 첨부파일을 답변·문제 해결에 사용합니다. 신분증·알림 토큰·인증키 등 문의에 필요하지 않은 개인정보나 비밀정보는 보내지 마세요.

## 3. 보관 및 보호 방법

서버에 저장하는 설치 식별자에는 원래 값을 직접 저장하는 대신 단방향 HMAC 변환을 적용합니다. 알림 전달 토큰은 암호화하여 저장하고, 앱과 자체 서버의 통신에는 HTTPS를 사용합니다. 보호 조치 후에도 추적 기록은 같은 앱 설치와 연결될 수 있으므로 완전히 익명화된 데이터는 아닙니다.

앱은 마지막 버스 조회 결과를 기기 내부 캐시에 저장합니다. 설치 식별자, 추적 재시도 상태, 동의한 안내 버전과 시각도 기기 내부 앱 저장소에 보관합니다. 기기 내부 데이터의 보관 기간은 서버 구독의 보존 기간과 별개입니다.

## 4. 외부 서비스와 국가 간 처리

서비스를 제공하기 위해 다음 외부 서비스를 사용합니다. 아래 서비스명은 이용하는 제품을 안내한 것입니다.

| 사용하는 서비스 | 처리 정보·목적과 전달 시점 |
| --- | --- |
| Google Cloud Run·Firestore | 앱 요청을 처리하고 원격 추적 구독을 저장합니다. 일반 조회 시 요청 정보가, 원격 추적 등록·갱신·중단 시 위에서 설명한 추적 정보가 네트워크를 통해 전달됩니다. |
| Google Cloud Logging | 요청과 서비스 동작 중 발생하는 접속·진단·감사 로그를 저장하여 서비스 운영과 장애 대응에 사용합니다. |
| Apple Push Notification service(APNs) | 원격 추적의 갱신·종료를 전달할 때 알림 대상 토큰과 도착 예정 시각·관측 시각·정보 만료 시각·상태 등 갱신 정보를 전송합니다. |
| 네이버 메일 | 이용자가 지원 이메일로 문의할 때 이메일 주소·본문·첨부를 수신·보관하고 답변을 전달합니다. |

Cloud Run과 Firestore는 서울 지역(`asia-northeast3`)을 사용합니다. Cloud Logging의 저장소 위치는 `global`로, 로그가 전 세계 데이터센터에 저장되거나 다른 데이터센터로 이동할 수 있습니다. 서울의 서버·데이터베이스 설정이 모든 정보의 국내 처리만을 뜻하지는 않습니다. [Google Cloud Logging 저장 지역 안내](https://docs.cloud.google.com/logging/docs/region-support)

Google의 공개 데이터 처리 부속약관은 제품별 데이터 위치 약정 등을 전제로 Google 또는 하위 처리자의 시설이 있는 국가에서 데이터를 처리할 수 있다고 설명합니다. 또한 보안 조치, 접근·비밀유지 의무와 하위 처리자의 데이터 이용 범위에 관한 조건을 정하고 있습니다. 서비스별 하위 처리자와 처리 국가에 관한 공개 목록은 Google이 관리합니다. [Google Cloud 데이터 처리 부속약관](https://cloud.google.com/terms/data-processing-addendum), [Google Cloud 하위 처리자 목록](https://cloud.google.com/terms/subprocessors)

APNs 전달은 Apple의 외부 서비스에서 처리됩니다. Apple의 공개 개인정보처리방침은 국가 간 이전·접근 가능성과 Apple이 수집한 개인정보의 일반적인 미국 저장을 설명합니다. 이는 이 앱의 개별 APNs 요청이 처리되는 모든 국가를 특정한 설명은 아닙니다. Apple은 해당 방침에서 저장 위치와 관계없이 보호 조치를 유지한다고 안내합니다. APNs 연결에는 암호화된 통신이 사용됩니다. [Apple 개인정보처리방침](https://www.apple.com/legal/privacy/en-ww/), [APNs 연결·전달 안내](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)

원격 추적을 원하지 않으면 추적 시작 안내에서 취소하거나 아래 방법으로 동의를 철회할 수 있습니다. 이 경우 새 원격 추적은 시작하지 않으며 일반 버스 조회는 계속 이용할 수 있습니다. 일반 조회에서도 서버의 요청 처리와 로그 기록은 이루어집니다. 지원 메일은 이용자가 문의를 보낼 때 처리합니다.

## 5. 보존 기간과 삭제

활성 추적 정보는 추적이 종료 처리될 때까지 버스 정보 갱신에 사용합니다. 서버는 등록·갱신 요청의 만료 시각과 최초 도착 예정 시각 등을 기준으로 만료 시각을 정하며, 사용자의 중단 요청이나 만료에 따라 추적을 종료합니다. 종료 처리 후에는 아래 종료 구독 기준을 적용합니다.

| 데이터 | 보존·삭제 기준 |
| --- | --- |
| 활성 버스 추적 | 추적 종료 처리 시까지 갱신에 사용합니다. 등록·갱신 요청의 만료 시각과 도착 예정 시각 등에 따라 종료 시점이 정해집니다. |
| 종료된 추적 구독 | 종료 기준으로 7일 후 자동 삭제 대상이 됩니다. Firestore의 비동기 삭제 처리 때문에 실제 삭제까지 추가 시간이 걸릴 수 있습니다. |
| 일반 요청·애플리케이션 로그 | 기본 로그 저장소에서 30일 보존합니다. |
| 클라우드 필수 감사 로그 | 클라우드 자원 관리 등의 필수 감사 로그 저장소에서 400일 보존합니다. 모든 버스 추적 기록을 400일 보관한다는 의미는 아닙니다. |
| APNs 전달 대기 알림 | Apple이 즉시 전달하지 못한 알림은 APNs 정책에 따라 최대 30일 보관될 수 있습니다. 앱 서버의 종료 구독 보존 기간과 별개입니다. |
| Firestore 문서 버전·관리형 백업 | 현재 설정에서는 최근 1시간의 문서 버전이 유지됩니다. 2026년 10월 15일 설정 확인 시 장기 시점 복구(PITR)는 비활성이며 예약 백업 일정과 서울 지역의 현존 관리형 백업은 없었습니다. |
| 문의 이메일·첨부 | 문의 처리 종료 후 30일 이내에 운영자가 관리하는 받은편지함·보낸편지함의 문의 기록과 내려받은 첨부 사본을 삭제합니다. |
| 기기 내부 데이터 | 앱의 저장소와 캐시에 보관합니다. 완료된 추적 삭제 재시도 상태는 정리되며, 설치 식별자에 별도의 7일 만료를 적용하지 않습니다. 앱 데이터를 삭제하면 해당 기기의 앱 저장소가 제거됩니다. |

운영자는 현재 실제 사용자 추적 기록과 요청 로그를 수동으로 내보내어 개인 PC나 다른 저장소에 별도 사본으로 보관하지 않습니다.

추적 중단은 원격 갱신을 끝내는 처리이며, 이미 저장된 구독 기록과 로그를 즉시 전부 삭제하는 처리가 아닙니다. Firestore 자동 삭제와 외부 제공자의 삭제 처리는 즉시 완료되지 않을 수 있습니다. 문의 메일 삭제는 운영자가 관리하는 사본에 적용되며 메일 제공자가 자체적으로 유지하는 모든 사본·로그의 즉시 삭제를 뜻하지 않습니다. [Firestore 자동 삭제 안내](https://docs.cloud.google.com/firestore/native/docs/ttl), [Firestore 문서 버전 안내](https://docs.cloud.google.com/firestore/native/docs/pitr), [APNs 전달 대기 안내](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns)

## 6. 이용자의 선택과 개인정보 문의

잠금화면 버스 추적을 사용하지 않아도 일반 버스 도착 조회를 이용할 수 있습니다. 원격 추적을 처음 선택하면 데이터 처리 안내와 `동의하고 추적`·`취소`를 표시합니다. 동의한 안내 버전과 시각은 기기에 저장합니다. iOS의 알림·Live Activity 사용 설정은 이 앱의 데이터 처리 안내에 대한 선택과 별개입니다.

앱의 `개인정보 처리 및 문의`에서 `동의 철회 및 추적 중단`을 선택하면 현재 추적을 중단하고 이후 새 추적에는 다시 동의를 요청합니다. 이미 전송 중이던 등록 요청은 완료될 수 있으며 앱은 해당 구독의 중단을 요청합니다. 동의 전이나 철회 후에도 이전에 등록된 추적을 정리하기 위한 중단 요청은 전송할 수 있습니다.

추적 중에는 앱의 `추적 중단` 또는 `잠금화면 추적 중단` 버튼으로 현재 버스의 원격 갱신 중단을 요청할 수 있습니다. 네트워크가 끊긴 경우 연결을 확인하고 앱을 다시 열어 주세요. 앱이 보류 중인 서버 중단 요청을 재시도합니다.

시스템 설정에서 앱의 Live Activity 사용을 해제할 수도 있습니다. 앱 삭제나 시스템 설정 변경만으로 서버 기록이 즉시 삭제되지는 않습니다. 서버에 남은 기록에는 위 보존·삭제 기준이 적용됩니다.
